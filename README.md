# Place4Market: вёрстка сайта и админки (вариант C)

PHP 8+, без фреймворков. Стили на CSS-переменных, JS на vanilla. Отступы табами.

## Запуск

```
php -S localhost:8000
```

- Сайт: http://localhost:8000/
- Админка: http://localhost:8000/admin/

## Языки

- Язык берётся из `?lang=en|sr-latn|sr-cyrl`, затем запоминается в cookie, по умолчанию `en`.
- Все внутренние ссылки строятся через `url('page.php', [...])` (внутри `lang_link()`), переключатель языка — через `lang_url()`. Чтобы перейти на SEO-адреса (`/sr/oglasi/...`), меняются только эти две функции + `.htaccess`.
- В `<head>` уже есть `hreflang` для всех трёх версий.
- Тексты интерфейса: `t('key')`, множественное число: `tp('cat.count', $n)` (сербские формы 1 / 2–4 / 5+).
- **Кириллица генерируется из латиницы:** правите `sr-latn.php`, затем `php source/lang/build-cyrillic.php`. Аббревиатуры, бренды и `{плейсхолдеры}` остаются латиницей (список исключений в `sr_cyr()`).
- Пользовательский контент (заголовки, описания, сообщения) хранится как `['en' => …, 'sr' => …]`, кириллица делается на лету через `tc()`.
- Тексты информационных страниц (о нас, помощь, безопасность, условия, приватность) лежат так же, в `source/inc/content/*.php`, а не в языковых файлах: это контент, его заменят целиком после семантического ядра. Почту и адреса в эти тексты не пишем — транслитерация их испортит.

## Данные

Всё тестовое лежит в массивах (`source/inc/data.php`, `data-common.php`, `admin/data.php`). Даты относительные (`ago('-2 hours')`), поэтому демо всегда «свежее». При подключении БД заменить массивы на запросы — вёрстка не меняется.

На сайте работает реальная фильтрация по тестовым данным: категория, поиск, город, цена (EUR → RSD по курсу `EUR_RATE`), состояние, «можно торговаться», сортировка, пагинация.

## JS: что где

Сайт (`main.js`), всё через data-атрибуты:

| Атрибут | Что делает |
|---|---|
| `data-fav` | сердечко «в избранное» (на странице избранного + `data-fav-remove` убирает карточку) |
| `data-tabs` + `role="tab"` | вкладки; `data-tabs-hash` — открытая вкладка в адресе (`#settings`) |
| `data-pills="listId"` | фильтр по статусу в «Моих объявлениях» |
| `data-drawer-open="filters"` | фильтры выезжают слева на планшете/телефоне |
| `data-dialog-open="id"` | открыть `<dialog>` |
| `data-confirm` (+ `data-remove-target`, `data-done`) | подтверждение удаления |
| `data-gallery` | галерея: стрелки, миниатюры, клавиатура, свайп |
| `data-reveal-phone` | «Показать номер» |
| `data-share` | поделиться / скопировать ссылку |
| `data-view-toggle` | сетка / список (запоминается) |
| `data-post-form` | подача: подкатегории, фото (drag & drop, обложка, удаление), живое превью |
| `data-chat` | диалоги, отправка (Enter), быстрые ответы, поиск |

**Демо-заглушки** (убрать при подключении бэкенда): `data-toast="…"` на кнопках, `data-demo="…"` на формах и `data-toast-on/off` на переключателях показывают уведомление вместо запроса к серверу.

Фото в форме подачи пока только показываются в превью. Для реальной загрузки с порядком/обложкой нужно отправлять файлы через `FormData` из массива `photos` в `main.js`.

## SEO

Каждая страница до подключения `header.php` задаёт в `$page`: `title`, `description`, `canonical` (`[путь, параметры]` без языка), `robots`, `schema[]` (JSON-LD), `og_type`/`og`. Тег `<head>` собирает `seo_head()` из `source/inc/seo.php`. На страницах с `noindex` (служебные, выдача с поиском/фильтрами/сортировкой) canonical и hreflang не выводятся.

Пока идёт разработка, сайт закрыт от индексации заголовком `X-Robots-Tag: noindex, nofollow` — в `.htaccess` и в `source/inc/bootstrap.php` (блоки `DEV-ONLY`, снять оба при запуске).

## Журнал ошибок и действий

`source/inc/log.php` подключается первым в обоих bootstrap и ловит всё, что падает дальше: предупреждения PHP, необработанные исключения, фатальные ошибки (в том числе нехватку памяти и ошибки разбора). Ошибки JS приходят из `main.js` и `admin.js` на `js-error.php`.

```php
log_event('error', 'Mail not sent', ['to' => $email]);    // уровни: debug, info, warning, error, critical
log_exception($e);                                         // пойманное исключение, с трассировкой
log_action('listing.delete', ['id' => 1048]);              // журнал действий (кто, что, над чем)
log_set_user($id, 'admin');                                // кто действует (в админке уже задан)
```

- Формат: одна запись JSON на строку, файл на день (`2026-10-29.log`), хранение 90 дней. В записи: время, уровень, канал (`app`, `audit`, `http`, `js`), сообщение, id запроса, адрес, IP, пользователь, браузер, контекст.
- Где лежит: на хостинге — `app-logs/` рядом с `public_html` (вне сайта), при `php -S` — `logs/` в проекте (в `.gitignore`). На другом сервере путь задаёт переменная окружения `P4M_LOG_DIR`. Если папка недоступна, записи уходят в журнал PHP сервера.
- Пароли, токены и похожие поля (`password`, `token`, `csrf`…) в контексте и в адресах заменяются на `***`; аргументы функций в трассировку не попадают.
- При фатальной ошибке недорисованная страница заменяется страницей 500 с кодом ошибки (это id запроса, он же в заголовке `X-Request-Id`): по коду запись находится в журнале. При `php -S` на странице видна сама ошибка, на проде — нет.
- 404 тоже пишутся (канал `http`): битая ссылка с нашей же страницы — `warning`, заход извне — `info`.

## Фото объявлений

Правила (размеры, качество, обработка) — в `CLAUDE.md`, раздел 2. У объявления в `images` лежит список фото, первое — обложка:

```php
['path' => 'img/demo/1048-1', 'color' => '#938e85', 'sizes' => [1920 => [1920, 1280], 960 => [960, 640], 480 => [480, 320], 200 => [200, 133]]]
```

Файлы — `source/<path>/<размер>.webp`, размер = длинная сторона. Выводит их `photo($photo, $sizes, $opts)` (`helpers.php`, общий для сайта и админки):
- в `srcset` все размеры (или до `max`), `width`/`height` для пропорций, средний цвет фоном до загрузки — CLS 0;
- `sizes` по месту — `PHOTO_SIZES` в `site.php` (карточка, галерея, миниатюра, строка, чат), потолок размера — `PHOTO_MAX`; в галерее фото вписывается целиком (`pic--contain`), `photo_sizes_contain()` уменьшает `sizes` для вертикальных;
- `lazy` по умолчанию; у первых четырёх карточек выдачи и главной — без него (`$cardEager`), у первой и у главного фото объявления — `fetchpriority="high"` (`$cardPriority`, `priority`).

На странице объявления обложка уходит в `og:image`, все фото — в `Product.image`. Без фото выводится заглушка с иконкой категории (`placeholder()`).

Демо-фото — бесплатные с Pexels, нарезаны так же, как будет нарезать сервер; список и скрипт — локально в `doc/tools/demo-photos.py`. С бэкендом `demo-photos.php` и `source/img/demo/` удаляются, данные идут из БД.

## Ассеты и кэш

CSS, JS и иконки подключаются через `asset('css/site.css')` → `source/css/site.css?v=<дата изменения>`, поэтому их можно кэшировать на год. Шрифты подключаются без версии: изменённый шрифт кладём под новым именем.

CSS и JS минифицируются при деплое (esbuild в `.github/workflows/deploy.yml`), в репозитории лежат читаемые исходники. Локально (`php -S`) работают исходники как есть.

## Адаптив

Сайт: десктоп ≥1440 (базовые стили), ноутбук ≤1439, планшет ≤1023, телефон ≤767; телефон рисуется под 360 и держится до 320. Админка: десктоп ≥1024 и мобильный ≤1023.

## Цвета и шрифты

`source/css/variables.css`: терракота `--color-accent`, олива `--color-olive`, морской `--color-sea`, бумажный фон `--color-bg`. Шрифты Lora (заголовки, цены) и Source Sans 3 (текст), обе с кириллицей, лежат в `source/fonts/` (`@font-face` в начале `variables.css`, Google Fonts не используется). Браузер грузит только нужные наборы символов; запасные шрифты подогнаны по метрикам, чтобы при загрузке ничего не прыгало. Для текста на светлом фоне используется `--color-accent-ink` (контраст AA), основной терракотовый — для кнопок с белым текстом.
